# Theme a project

A theme gives a project its own colours and font without changing any
component. It is generated by the `zebra-theme` tool from a small file,
never written by hand, so it holds in light, dark and the higher-contrast
modes.

Talk to the designer as `designer-project-onboarding` says under Talking with the
designer: call the system "the Design System", use plain short words, and
put what they need to answer inside each question's dialog. Say "your brand
colour", not "the ramp". Don't show commands or file names unless asked.

## 1. Find the tool

Use the first that exists, and use it for every command below. Never ask the
designer to install anything to get it.

1. **The project has the packages:** `npx zebra-theme`. It is there when
   `node_modules/@zebra-design-system/tokens/bin/zebra-theme.mjs` exists.
2. **The plugin's own copy:** `node "<plugin>/tools/zebra-theme/bin/zebra-theme.mjs"`,
   where `<plugin>` is the folder two levels above this skill's folder (the
   one that holds `skills/` and `tools/`). It works with nothing installed.

If neither exists, this skill was installed without the plugin and without
the packages: say so plainly, and that updating the Design System plugin or
installing its packages fixes it. Don't hand-write a theme instead.

The plugin's copy is as new as the plugin. When both exist and the project's
packages are older than the plugin, use the project's: its theme has to
match the tokens the project actually loads.

Below, `zebra-theme` means whichever you found.

## 2. Find out what to change

Read `zebra-context/PROJECT.md` and `THEME.md` if the project has them. A
project with a theme already is being changed, not started: read
`zebra-context/<project>.theme.json` and keep what the designer isn't
changing.

Get the look from the first that applies:

- **A Figma design or a codebase:** read the colours and font it really
  uses, as `designer-project-onboarding` does in its review.
- **A brand guide or a colour the designer gave:** use that.
- **Nothing yet:** ask, in one dialog: "What should change?" (**The brand
  colour** / **The grey tones** / **The font** / **Use a look the Design
  System already has**), then ask for the colour or the font name in one
  plain line.

A project that has no context yet still gets a theme. Name it from the
folder, and offer `designer-project-onboarding` afterwards for the rest.

## 3. Check each colour against the system

For each colour, run `zebra-theme --ramp=<colour> --like=<ramp>`. It answers
two things:

- **Is it already a Design System colour?** If it says so, don't make a new
  one. Tell the designer ("That blue is already in the Design System"), and
  point the brand at the existing colour, or use the shipped extension that
  has it (`zebra-theme --list` ends with the list of them).
- **What full set of shades does it make?** It prints them. Each shade keeps
  the lightness of the one it replaces, so text stays readable.

Tell the designer which shade carries their exact colour. A brand colour
much darker or lighter than the Design System's button colour won't be the
button colour itself: the button takes the nearest shade that stays
readable, and the exact colour is kept for the logo and brand touches. Show
both in the dialog and ask: **Use the readable shade for buttons**
(recommended) / **Change the brand colour I gave**.

## 4. Write the theme and generate it

Follow `references/THEME.md` in the `designer-project-onboarding` skill for the
theme file, the font and special treatments. In short:

- write `zebra-context/<project>.theme.json` with the shades from step 3;
- run `zebra-theme zebra-context/<project>.theme.json zebra-context/theme.css`;
- **Problems:** it writes nothing until they are fixed. Fix the file;
- **Contrast lost:** each line is text that was readable before and isn't
  now. Adjust that shade and run it again until no line is left. Never hand
  over a theme with one left.

A theme never changes status colours (red, amber, green), spacing, sizes or
the type scale. If the designer asks for one of those, say it stays the
Design System's, and why: people learn those across every product.

## 5. Show it

Put the theme on a prototype: load `theme.css` after the Design System's
styles and add `ext-<project>` to the page root, beside the mode class. With
no prototype yet, make a small sample page: a primary button, a link, a
selected control, a form field in focus, a card, in each of the project's
modes.

Look at it in each mode before handing over. Then ask: **Looks right** /
**Change something**.

## 6. Save and report

Update `zebra-context/THEME.md` with what changed, and `PROJECT.md`
(`level: themed`, `theme: <project>`, a line in Decisions). Tell the
designer, in a few plain lines:

- what changed, and what it looks like now;
- any colour that was already in the Design System;
- anything they asked for that stays the Design System's;
- that the theme is saved with the project and applies to every prototype.
