Distribution

Zeta Web is released with the others now. It was @zebra-fed/zeta-web on its own 1.x line; from 0.5.1 it is @zebra-design-system/zeta-web, always at the same version as the React and web component libraries, in the same pnpm workspace. Existing projects change the package name in installs and imports; the old zeta-web-v1.x tags stay installable. From 0.6.0 it also draws its icons from @zebra-design-system/icons like the other two libraries; names with underscores still work, and there is no icon copy step.

Six packages leave this repo. Versioning rules are in VERSIONING.md; the release pipeline is .github/workflows/release.yml; the full plan is the Zebra Distribution Plan artifact.

Verified 20 November 2026: a fresh project installs web-components and tokens straight from GitHub, icons and patterns arrive through version tags with no registry, and npx zebra-skills installs all six skills. docs/cdn-smoke.html is ready for the first real npm release.

Consumer onboarding is one page: the Zebra Quickstart artifact (source docs/start/index.html) walks builders and designers from plugin install to building from Figma, a brief or a sketch. Share it from its Share menu — it starts private.

Eight consumer skills ship in the library tarballs and the Claude Code plugin (0.7.3): zebra-figma-to-code, zebra-build-ui, zebra-prototype, zebra-onboard-project, zebra-theme, zebra-handoff, zebra-ux-patterns and zebra-ux-audit. zebra-handoff writes a build spec for developers from a finished prototype; it is in the plugin from 0.6.0 and the libraries from 0.7.1. zebra-theme (plugin 0.7.0) gives a project its own colours and font. Before it, theming was only a step inside onboarding and needed the tokens package installed in the project, so people with the plugin alone could not reach it. The plugin now carries its own copy of the theming tool, with a /zebra-theme command. Plugin 0.7.0 shipped the tool without its data, because the repo ignores folders named dist; 0.7.1 fixes it, and the release check now fails if any file of the tool is ignored by git. zebra-onboard-project walks a designer through a short setup and saves the project's context in a committed zebra-context/ folder, which every later prototype and audit reads. Authored once in distribution/skills/; npx zebra-skills installs them in a consumer project.

From 0.6.1, zebra-prototype opens an empty folder with a start dialog (Free exploration, Figma reference, From a repo). With a Figma reference it matches the design's variants, spacing and text styles, asks the designer about obvious deviations, and compares the result by measurement. Every prototype gets a visual review before hand-over. From 0.6.2 it also brings the design's pictures over: photos as their original files in an assets/ folder, logos and illustrations as inline SVG, never an icon or a placeholder in their place. From plugin 0.6.1, a project that starts from a Figma design or a codebase is first built to match it strictly, with custom components kept under 20%, and nothing made up: no extra functionality or data. After that first build the skill lists the parts it adjusted and asks whether to switch them to the Design System's own versions. The skills speak to designers in plain words, call the system "the Design System", and read Companion and AI use from the source. From plugin 0.7.2, onboarding from a design or a codebase asks, straight after the review, whether prototypes should match the project's look. On yes it matches the look and feel as closely as possible and keeps the style changes in zebra-context/overrides.css; on no it builds from the Design System as it comes. From plugin 0.7.3, choosing to match means one-to-one parity with the source, in look and in structure, ahead of using the Design System's parts. The 20% limit on custom parts is gone. After building, the skill checks parity against the Figma design or the code, fixes the gaps itself and repeats until none is left. It asks nothing on the way: no setup questions, no confirmation and no question after the build, only a report. The one question left is whether to make up data for a screen that needs live data.

Patterns 0.2.0 adds patterns/compositions/: seven screen recipes by the person's job, with the organisms and spacing steps they use. They are edited by hand; packaging writes them to graph.json and guards every name and rule number in them. The spacing values in zebra.md and the recipes are a first draft to review.

Released in 0.7.0 (20 November 2026): Navigation Rail has showDivider, which turns the divider on its trailing edge on or off, from the new Show Divider property in Figma. It is on by default in react-baseui and web-components, and show-divider is off by default in zeta-web. Also in 0.7.0: the skills never import icons from Figma and use the closest glyph instead. The Navigation Rail spec also changed: the rail follows the page's mode by default, inverse shows the opposite shade, and a new locked keeps its default or set mode. All three libraries now do this; a locked rail is dark, or light with inverse. Existing rails on a light page turn light on upgrade unless they add locked. The Global Header spec gained anchored (a floating rounded header when false) and showProfile; all three libraries now have both. A rounded header's bar has square corners unless anchored is false; the floating bar also takes the medium shadow.

A project's own theme is generated, never hand-written. The tokens package ships the token builder and a zebra-theme command: npx zebra-theme <name>.theme.json builds .ext-<name> from a small file of overrides, the way the shipped extensions are built, so it holds in every mode and on any container. It refuses names that are not tokens and reports text contrast the theme loses. It ships in tokens 0.3.0.

The UX patterns are edited in patterns/: ten plain Markdown files of numbered rules for how screens are composed and behave, with no component or token names. Add to and organise them with the zebra-pattern-ingest skill, or edit them by hand, then run pnpm run docs:components, which also regenerates the manifest the skills read. Guard rails run at that point and stop with the file and line if a rule file names a token or a Zebra component, a rule number is used twice or points nowhere, a link is broken or a file is unlisted. They also ship alone, as the zebra-patterns plugin, so a product on another component system can be audited with zebra-ux-audit. Ask the skill for a rule in plain words: it asks which pack the rule goes in, checks that it contradicts no existing rule and walks you through the choice if it does, then files it and keeps the pack tidy. It adds compositions the same way, into patterns/compositions/, at any size: a whole screen, a header or footer area, or a single dashboard card. If you can't describe the layout, it asks for a Figma design that shows it and reads the parts, spacing and changes out of the design. In patterns 0.3.0 the compositions were emptied (21 November 2026) to start again: the seven drafted screen recipes and their blocks are gone, the spacing steps stay, and new ones are added through the skill. Compositions are reference ideas, never rules: the skills use one as a starting point, a screen that differs from it has broken nothing, and only the numbered rules decide what an audit reports (plugin 0.6.2).

Known gaps

Checked on 7 November 2026. Expect these to come up when you run the playbooks.

GapWhat it means for you
AAA in web-componentsAvatar initials and System Banner fail. React already has both fixes.
AAA in zeta-webSame two failures, and legacy components ignore AAA modes until they move to Zebra tokens.
Condensed extensionThe tokens exist and the Review example above offers it, but no Storybook toolbar does yet.
Dark error colourDark status/error/default is now negative/50, following Figma. White text on it is 3.11:1, so eight Zeta Web contrast tests fail for negative buttons, indicators, labels and the urgent pill.
Target extensionRemoved from Figma on 17 November 2026. It is gone from tokens/, the packages' CSS and the Storybook toolbars as of tokens 0.2.0.
StepperBuilt from specs/stepper in all three packages. Grey rail-step labels are below AA contrast, as designed.
Published libraryBehind the Figma file: surface/overlay and surface/shade aren't published yet, so Figma rebuilds still bind surface/dialog for overlays.
Inline BannerBuilt from specs/inline-banner in all three packages; in zeta-web it is the refined zeta-in-page-banner. White text on solid neutral, and on solid warning in dark mode, is below AA contrast.
Help popoversFigma's help popover, a white card with a title and paragraphs, has no component. Tooltip takes one short line, so pages build it from a Card.
Input clear controlInput always shows its clear (close) control while you type in a field with a value. It needs a prop to turn it off.
Block behaviourInput and Select both take block. Without it, a field starts at 280px and never grows past its container. With it, the field fills the container. For a form column, set the column's width (Figma's 400px, for example) and let the fields fill it. Then switch rows span the same column, and each switch ends where the fields end.
Header and rail theme lockGlobal Header and Navigation Rail lock their own mode whatever the page's mode. mode and inverse only swap dark for light. They need a prop to follow the page's mode instead.
Message InputBuilt from specs/message-input in all three packages (17 Nov 2026). React moved out of /experimental. The web component and Zeta Web show image attachments as a file chip, without React's thumbnail.
Chat MessageBuilt from specs/chat-message in all three packages (17 Nov 2026). Figma has no first assistant message in a channel, and the spec lists Figma inconsistencies the builds follow as intended.
File UploadBuilt from specs/file-upload in all three packages (17 Nov 2026). Zeta Web's refined elements drop active, boolean error and flavor (breaking). Its ring shows the percentage inside the circle.
Automatic releasesChangesets and the Release workflow cover all six packages; publishing to npm stays dormant until the npm org and NPM_TOKEN exist.
Spec noiseA 7 November review flagged 43 of 48 specs for noise: extraction diaries, resolved issues kept as changelog, the same prose repeated. Corrections are in specs/spec-noise-corrections.md; new spec writing follows specs/spec-writing-guidance.md. The specs themselves are unchanged.

Figma Status

Every main component on the Figma file's component pages, and whether each library builds it from a spec. Subcomponents, the sets in a page's Subcomponents frame, are left out.

  • From spec The library's source names the spec that covers this component.
  • Experimental Built as an experiment, with no spec. Not for product use.
  • Not from spec An element of this name exists, but nothing ties it to a spec.
  • Not built The library has nothing for it.
