Zebra Design System · for builders and designers

From zero to an on-system screen with Claude Code

One repo URL gives you everything: the component packages, three skills that build with them, and the setup command that wires a project. You describe the screen — in words, a Figma link, or a photo of a sketch — and Claude composes it from the real library with semantic tokens, themed for light and dark from the first render.

1Install the plugin — once per machine

Everything installs from the repo itself; there is no npm account or registry anywhere. In any terminal with Claude Code:

claude plugin marketplace add "https://github.com/zebratechnologies/zebra-design-system.git#design/init"
claude plugin install zebra-design-system@zebra-design-system
  • You get three skills — zebra-figma-to-code, zebra-build-ui, zebra-prototype — and two commands: /zebra-setup and /zebra-components.
  • Every skill reads the shipped DESIGN.md and AGENTS.md before touching your code, so output follows the system's rules, not Claude's defaults.
  • The #design/init ref is temporary: once the branch merges to main, re-add the marketplace by plain repo reference so claude plugin update tracks it.

2Fastest path: a shareable prototype

No app required. An empty folder plus two installs is enough for the zebra-prototype skill to bundle the system and publish your idea as a private claude.ai page you can share for review:

mkdir zebra-proto && cd zebra-proto && npm init -y
npm i "git+https://github.com/zebratechnologies/zebra-design-system.git#dist/web-components" \
      "git+https://github.com/zebratechnologies/zebra-design-system.git#dist/tokens"
claude

Then just ask: "Prototype a parcel-tracking dashboard — status cards, a shipments table, a details panel — and publish it as an artifact I can share."

Claude bundles the installed components, tokens and icon font into the page, publishes it, and iterates on the same link as you refine. These are the real components:

Primary action Outline Text Rendered live by the same zds-* elements your prototype uses — switch your theme and they re-theme with the page.

3A fresh app — pick your technology

Three libraries share the same specs, tokens and icons; pick by stack. The simplest route is to let Claude do it — "Scaffold a new React app wired to the Zebra Design System, then run /zebra-setup to verify." — but the manual version of each is short:

React

Pick when the app is React 19 — components wrap Base UI primitives. 
npm create vite@latest my-app -- --template react-ts
cd my-app && npm i
npm i "git+https://github.com/zebratechnologies/zebra-design-system.git#dist/react-baseui" \
      "git+https://github.com/zebratechnologies/zebra-design-system.git#dist/tokens"
  • Icons arrive automatically as a tagged git dependency.
  • In src/main.tsx, once:
    import "@zebra-design-system/tokens/css";
    import "@zebra-design-system/icons/icons.css";

Web Components

Pick for any other stack, or none — zds-* custom elements work in plain HTML. 
npm create vite@latest my-app -- --template vanilla-ts
cd my-app && npm i
npm i "git+https://github.com/zebratechnologies/zebra-design-system.git#dist/web-components" \
      "git+https://github.com/zebratechnologies/zebra-design-system.git#dist/tokens"
  • In the entry, once:
    import "@zebra-design-system/tokens/css";
    import "@zebra-design-system/icons/icons.css";
    import "@zebra-design-system/web-components";

Zeta Web

Pick when the team already builds on the legacy zeta-* elements. 
npm i @zebra-fed/zeta-web
  • On npm today (1.3.6), and on #dist/zeta-web like the others.
  • Themes with attributes — data-theme="dark" — rather than mode classes.

Pin a version anywhere by swapping #dist/<pkg> for the tag, e.g. #react-baseui-v0.1.0. Branches always serve the latest release.

4An existing codebase or boilerplate

Install the packages for your stack as above, then let the setup command find what's missing instead of wiring by hand:

claude
> /zebra-setup

It checks the packages, adds the two entry imports if absent, renders a component and toggles dark mode to prove theming actually reaches it, installs the skills, and ends with a status table. A hard-coded colour somewhere? It finds the cause rather than patching the symptom.

Three ways to design, one system

However the idea arrives, the same rules hold: library components first, semantic tokens for every value, shape chosen once at the root, dark mode for free. Claude reports any gap it hits — a missing token, a component that doesn't exist — instead of papering over it; pass those reports to the design system team.

From a Figma design

Translation, not invention — the design was built from the same library.

Paste a frame link: "Build this screen in my app: figma.com/design/…?node-id=…"

  • Needs the Figma MCP connected in Claude Code (Settings → Connectors, or claude mcp add).
  • Every Figma instance becomes the installed component with the same variants; every bound value becomes its token; text styles match exactly.
  • Explicit dark or brand frames keep their mode; dividers drawn in Figma are drawn in code.

From a brief — vibe it

No design yet? Describe the screen and let the system make it look designed.

"Design a warehouse check-in flow: scan step, exceptions list, confirmation. Sharp shape, dark-friendly, one primary action per view."

  • Claude composes from the installed library and the type scale — a hand-made button or hex colour is treated as a bug.
  • Say as much or as little as you like; the DESIGN.md principles fill the gaps.

From a sketch or screenshot

A whiteboard photo, a napkin sketch, a screenshot of another product.

Drag the image into the chat: "Rebuild this on the Zebra system — keep the layout, replace every element with our components and tokens."

  • Claude maps each drawn element to the nearest library component and names what didn't map, so the sketch becomes an on-system screen, not a pixel copy.
  • Works for modernising screenshots of legacy UI too.

While you work

  • /zebra-components — ask what exists before building it: "is there a stepper?", "what flavours does Button have?" Answers come from the shipped catalog for your installed version, never from memory.
  • Toggle mode-dark on the root (Zeta: data-theme="dark") whenever you review — if something breaks in dark, a literal value sneaked in.
  • After a package update, run npx zebra-skills again so project-local skill copies match the installed version.
