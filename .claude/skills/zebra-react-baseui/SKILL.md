# Zebra React (Base UI)

`packages/react-baseui` ships the design system as **React components
wrapping Base UI primitives**. Base UI brings behaviour and accessibility;
this package brings the visual layer and nothing else. It is a **sibling** of
`packages/web-components`, not a layer on top of it — they share the token
CSS variables, the icon font and the component specs, and no code.

Read [references/code-style.md](references/code-style.md) before writing a
component.

## The division of labour

| Base UI owns | We own |
|---|---|
| Focus handling, `focusableWhenDisabled` | Every colour, dimension, radius and type value |
| Disabled semantics and `[data-disabled]` | The `data-flavour` / `data-size` / `data-shape` attributes |
| The `render` prop for polymorphism | The CSS keyed off those attributes |
| Keyboard interaction, ARIA wiring | Which token each state reads |

If you find yourself reimplementing focus, keyboard handling or disabled
semantics, stop: either the primitive already does it, or you are wrapping
the wrong primitive.

## Where everything lives

| What | Where | Generated by |
|---|---|---|
| **Specs** | `specs/<component>/<component>.spec.json` + `.spec.md` | `zebra-figma-component-spec` skill |
| **Tokens (source)** | `tokens/` at the repo root — DTCG JSON | `zebra-figma-token-export` skill |
| **Tokens (CSS)** | `packages/react-baseui/src/tokens/*.css` | `../web-components/scripts/build-tokens-css.mjs` — **never edit by hand** |
| **Icon font** | `packages/icons/` — `fonts/`, `icons.css`, `codepoints.json`, `icon-names.ts` | `zebra-figma-icon-font` skill |
| **Text fonts** | `src/tokens/fonts.css` — IBM Plex Sans from Google Fonts | derived from the font tokens |
| **Components** | `src/components/<name>/<Name>.tsx` + `<name>.css` | you |
| **Stories** | `stories/<Name>.stories.tsx`, titled `Components/<Name>` | you |

This package has no token script of its own — `pnpm run tokens` invokes the
web-components one with explicit in/out paths, so both packages generate from
the same source and cannot drift.

Point the implementation at its spec with a `@spec` tag in the component's
JSDoc and a `Spec:` line at the top of the CSS file.

## Commands

```bash
cd packages/react-baseui
pnpm run tokens       # tokens/ -> src/tokens/*.css
pnpm run check        # tokens + typecheck + theming assertions
pnpm run storybook    # http://localhost:6008
```

## Building a component from a spec

1. **Read the spec**, both files — including `issues`, so you do not
   faithfully reproduce a known defect.
2. **Pick the Base UI primitive** that carries the behaviour. If none fits,
   say so rather than hand-rolling accessibility.
3. **Create `src/components/<name>/`** with `<Name>.tsx` and `<name>.css`
   (see code-style.md), mirroring the spec's anatomy and variant table in its
   own section order.
4. **Bind only unprefixed semantic tokens** —
   `--interactive-primary-background-default`, not `--palette-*` or
   `--primitives-*`, which are internal layers the theme system moves
   underneath you.
5. **Export the component and its types** from `src/index.ts`.
6. **Write `stories/<Name>.stories.tsx`**, one export per spec axis. Not
   optional — a component with no story is not done, and it is how the spec's
   variant table becomes something reviewable in Storybook.
7. **Run `pnpm run check`, then the visual audit.** Both.
8. **Check parity with `packages/web-components`.** The same spec built twice
   should look the same — run both visual audits and compare the
   screenshots; this is the only place a divergence between the two packages
   shows up.

## Visual audit

```bash
node .claude/skills/zebra-react-baseui/scripts/visual-audit.mjs button
node .claude/skills/zebra-react-baseui/scripts/visual-audit.mjs button --keep   # leave .audit/ in place
node .claude/skills/zebra-react-baseui/scripts/visual-audit.mjs button --full   # cross product
```

Sweeps each spec axis against the defaults and renders every specimen in four
theme panes (light, dark, `.ext-companion.mode-dark`, and light nested in
dark), then asserts what only exists once painted: no collapse to zero
height, the size axis actually changing size, no label sharing its
background's colour, icon glyphs drawing, dark mode reaching the component
(not just the page), and nested `mode-light` returning to light. It also
renders every axis and flags any that changed **nothing** on screen — a React
prop can't be introspected the way a custom element's property can, so this
is the only way to catch an unwired prop.

**It prints a screenshot path. Open it.** The assertions catch collapse,
invisibility and broken theming; they cannot tell you a component is simply
the wrong shape — two cross-component bugs on Navigation Rail passed every
per-component check on this design system and were caught only by looking.

[references/visual-audit.md](references/visual-audit.md) explains what each
assertion means when it fails and how to extend the set.

Expected warnings on a faithful Button, not regressions: **contrast below
4.5:1** (real palette shortfalls, recorded in the spec's `issues` — compare
the count) and **the `state` axis having no visible effect** (hover, pressed
and focus are CSS states, never props).

## Icons

An icon is a **font glyph**, never an SVG.

```tsx
import { Icon } from "@zebra-design-system/react-baseui";

<Icon name="alarm" label="Alarm" />   // labelled, exposed to AT
<Icon name="add" />                    // decorative, aria-hidden
```

- **Load `@zebra-design-system/icons/icons.css` once** for the `@font-face`
  blocks. Storybook's preview does it; a consuming app must too.
- **The glyph takes `currentColor` and the inherited `font-size`** — the whole
  reason icons ship as a font. Never give an icon its own colour token inside
  a component.
- **`rounded` / `sharp` is a family swap, not a different glyph** — both
  share codepoints. Button pins the family from its own `shape`; say so in a
  comment where you do the same.
- **Check the name against `packages/icons/codepoints.json`.** Nine icons
  have no glyph (stroked paths, non-square viewBoxes) and are listed in
  `inventory.json`. Naming one renders nothing, silently.

Types come from the font, so a typo is a compile error:

```ts
import type { IconName } from "@zebra-design-system/icons/names";
```

## Theming

A class on any ancestor, cascading to everything inside:

```tsx
<div className="ext-companion mode-dark">
  <Button>Inherits companion dark</Button>
</div>
```

`ext-*` selects a brand extension, `mode-*` light/dark, `bp-*` a size and
typography mode. **There is no theme provider and nothing re-renders** — it
is the same CSS the web-components package uses, and works on plain HTML too.
A component that reads only semantic tokens gets this for free; one that
hard-codes a colour opts out of it permanently. Do not add a React context, a
`useTheme` hook, or a styled-components-style theme object — the cascade
already did it.

## Committing

Conventional Commits, enforced for release versioning:

```
feat(button): add gradient and text-gradient flavours
fix(icon): fall back to the rounded family when iconStyle is unknown
```

`feat:` minor, `fix:`/`perf:` patch, `BREAKING CHANGE:` major; `docs:`,
`chore:`, `test:`, `refactor:`, `style:` no bump. Full table in
`CONTRIBUTING.md`.
